# ID3 数据采集清单与交付要求

这份文档供真机采集、MuJoCo 仿真采集和离线整理人员使用。当前目标是：先用成对接触刺激训练两个 ViT，再冻结编码器，用仿真数据训练接触几何／深度图重建任务头，最后在真机 ID3 输入上评估。

**范围：只使用单片 ID3 的观测。** 本仓库接收采集后的文件；不修改 SDK、replay、碰撞求解或 RBF 采集过程。模型结构见 [architecture.md](architecture.md)，最终训练文件的严格字段见 [data_contract.md](data_contract.md)。

## 1. 最终要收集什么

| 来源 | 必需的模型输入 | 单帧形状 | 单位／坐标 | 从哪里获得 |
|---|---|---|---|---|
| 真机 ID3 | 每个 taxel 的 `Fx,Fy,Fz` | `[N,3]` | N，统一 ID3 局部坐标 | SDK 的实际逐 taxel 测量 |
| 真机 ID3 | 整片传感器的 `Fx,Fy,Fz` 合力 | `[3]` | N，同一 ID3 局部坐标 | SDK 的模块合力输出 |
| MuJoCo ID3 | 每个 taxel 的接触深度 | `[N]` | m，非负 | 上游保存的逐 taxel 几何／碰撞深度 |
| MuJoCo ID3 | 整片传感器的三轴接触合力 | `[3]` | N，作用在 ID3 上，同一局部坐标 | MuJoCo 接触求解器的直接合力 |

`N` 默认配置为 120；在 SDK 实际 taxel 数量和顺序核实前，不把默认值当作已完成硬件标定。真机全局合力应独立保存，不由本仓库用 taxel 求和替代。SDK 的 taxel 通道若不是三轴实际测量，需先解决采集能力，不能以合力拆分填充。

三轴分量必须保留符号，不只存力的模长。仿真不需要逐 taxel 力，不读取 RBF 分配的 taxel 力，也不需要把仿真做成与 SDK 相同的原始信号。

### RBF 与已有数据的处理

若 replay 同时保存了“直接接触合力”和“RBF 分配后的 taxel 力”，可以选用前者。上游代码先执行 `module[idx] += fs`，之后才做空间分配时，这个模块合力不会因另外存在 RBF 输出而失效。若只有分配后的 taxel 力，需要找到原始求解器合力记录；本仓库不通过求和、拟合或补零冒充该原始字段。

MuJoCo 的 `contact.dist` 是每个**碰撞接触点**的距离，不天然等于每个 taxel 的深度。采集端必须交付明确对应 taxel ID 的深度向量，并说明采用逐法向采样，还是已建立 taxel 碰撞几何及映射。不能把单个接触深度复制给所有 taxel。

## 2. 哪个阶段需要哪些数据

| 分区 | 需要真机输入 | 需要仿真输入 | 用途／标签 | 能否被用于选模型 |
|---|---|---|---|---|
| `align_train` | 是 | 是，逐刺激配对 | 对齐和全部模态重建，无须额外形状标签 | 用于优化；归一化只在这里拟合 |
| `align_val` | 是 | 是，逐刺激配对 | 计算验证对齐／重建损失 | 选择表示模型 |
| `downstream_train` | 否 | 是 | 当前帧 `sim_depth_m` 就是深度任务标签 | 优化任务头 |
| `downstream_val` | 否 | 是 | 同上 | 只按仿真验证误差选任务头 |
| `test_id` | 是 | 是，作为比较输入及几何标签 | 已知形状／尺寸、保留的位置／轨迹 | 只做最终测试 |
| `test_ood_size` | 是 | 是，逐刺激配对 | 保留尺寸或姿态条件 | 只做最终测试 |
| `test_ood_shape` | 是 | 是，逐刺激配对 | 保留形状条件 | 只做最终测试 |

“下游仅用仿真训练”不表示整个系统不需要真实训练数据：第一阶段明确需要成对真机与仿真观测。

默认先完成 `test_id`。OOD-Size 和 OOD-Shape 为后续扩展，不要在没有对应采集条件时给普通随机划分冠以 OOD 名称。真机深度标签目前来自经过验证的配对几何；没有外部几何真值时，它衡量的是对该配对参考的误差，不等于独立测量的皮肤形变误差。

## 3. 每次实验必须保留的原始记录

以下是**上游原始采集要求**。除第 1 节输入及数据契约列出的字段外，其余可以放在原始日志或 sidecar 文件中，不必全部输入网络。

| 项目 | 必须记录的内容 | 原因 |
|---|---|---|
| 记录身份 | `episode_id`、设备／传感器 ID、独立重复编号 | 可追溯、禁止跨轨迹拼接历史 |
| 触觉包身份 | 原始触觉包编号、原始时间戳、接收时间戳 | 识别机械臂行重复引用的触觉包 |
| 时钟 | SDK 时钟类型、主机单调时钟、仿真时间、回放源时间及偏移 | 构造共同时间轴，不把仿真 t=0 当作触发时刻 |
| 原始真机输入 | taxel 三轴读数、模块三轴读数、原始单位及有效状态 | 保留量化前后的换算关系，避免重复乘除比例 |
| 原始仿真输入 | taxel 深度、ID3 直接接触合力、传感器与物体状态 | 追溯力的来源和接触发生在哪片传感器 |
| 物理刺激 | 压头形状／尺寸、材质、相对位姿、压入量、速度、加载／保持／卸载阶段 | 证明同一帧对应同一种物理刺激 |
| 轨迹状态 | 实际关节／物体运动或可重建相对位姿的记录 | 支持 replay 与排查几何偏差；不要求作为网络输入 |
| 几何标定 | taxel ID／顺序／xyz／法向、传感器参考坐标系 | 保证位置编码与读数一一对应 |
| 力标定 | SDK 单位比例、零偏、坐标变换、轴方向、饱和范围 | 将两域三轴读数解释在相同坐标约定下 |
| 仿真设置 | MuJoCo 版本、MJCF／资源版本、传感器 geom、接触参数、步长、控制方法 | 力由碰撞模型与求解器共同决定，需要可重现 |
| 数据质量 | 丢帧、过期、无效、饱和、异常峰值、接触不一致标记 | 离线剔除或掩码，不以零代替缺失 |

纳秒时间戳存为整数或整数文本，避免先转浮点丢失精度。原始记录尽量保留，只在离线导出副本中换单位、去重或筛选。

### 坐标与零偏标定

1. 选定一个右手 ID3 局部参考系，绘出 X/Y/Z 正方向及表面法向约定。
2. 确认真机 taxel 三轴是模块公共坐标还是各 taxel 局部坐标；若各 taxel 不同，需要逐点旋转到公共系。当前通用适配器只接受已统一坐标的数组，不能自动推断这些旋转。
3. 对真机模块合力和 taxel 读数分别记录单位转换与无接触零偏。保留加载前／卸载后的无接触片段，用于检查漂移；不能把卸载残余信号直接当作丢帧。
4. 仿真合力须确认是**作用在传感器上**的力，而不是传感器施加给物体的反力；先统一每个接触的坐标和符号，再相加。
5. 用方向已知的轻载接触逐轴检查符号与量级，核对 taxel 顺序。不能仅通过设置元数据 `axis_calibrated=true` 代替验证。

实际零偏补偿应使用对应校准记录或仅过去可用的无接触信息；不要用测试任务标签拟合输入校准。

## 4. 推荐的采集过程

### 阶段 A：接口验收

先采 10–20 条短轨迹，用于验证接口而非训练最终模型。包括无接触、单处压入、保持、卸载及不同位置接触。检查四类输入是否真实存在、同步、可转换为统一单位；检查 ID3 的接触能否在仿真对应位置复现。

若真机 ID3 接触而仿真 ID3 深度始终为零，先修正上游位姿／几何／手型／碰撞设置，不进入表示训练。同样，真机原始数据只有模块合力而没有逐 taxel 三轴力时，需先补齐采集。

### 阶段 B：配对采集

在硬件已验证的量程和行程内覆盖：

- 不同接触位置：中心、边缘以及曲面区域，避免只在一个点训练。
- 多种压头形状和尺寸，并为 OOD 另留条件。
- 多个压入量／载荷档位，采集完整加载、保持和卸载过程。
- 不同速度与重复实验，覆盖迟滞和回程差异。
- 若需要利用三轴力，加入可控的倾斜或切向加载条件，确保仿真也能重建对应运动与接触；否则三轴通道可能大部分时间只有法向分量。
- 保留一定无接触背景，控制其比例，避免全零帧淹没接触样本。

一个可调整的**先导规模示例**是：3 种压头形状 × 5 个位置分组 × 3 个压入档位 × 2 种速度 × 2 次独立重复，共 180 条轨迹。它不是论文规模，也不保证足够训练；五类基本分区可先按不同位置分组规划，但每分区仅一个位置的统计很弱，正式评估应增加位置、独立重复及单独的 OOD 条件。具体行程和力上限由硬件实验确定，本仓库不预设安全量程。

若真实触觉频率约为 10 Hz，默认 10 帧历史覆盖首末采样间约 0.9 s。每条轨迹需包含足够长的连续独立触觉序列；实际频率不同，应调整采样方案与 `history`／`max_history_gap_s`。高频机械臂采样不等于同频独立触觉观测。

### 阶段 C：增加仿真下游数据

完成配对数据验收后，可在预先保留的下游训练条件中增加仅仿真的样本。继续保存深度和直接合力，不需要伪造真机输入。保持测试条件隔离，不把同一轨迹的相邻帧随机分到训练与测试。

## 5. 离线整理步骤

1. 保存不可变的原始采集记录、几何文件和仿真配置，生成来源清单。
2. 提取 ID3，核实 taxel 数量与排列；将力统一成 N、长度成 m、时间成 s，并完成坐标转换。
3. 按独立真机触觉包去重；依据共同时间轴匹配仿真帧，保存真实的带符号时间差。当前匹配是离线最近邻，不是在线因果同步承诺。
4. 验证接触位置与状态一致。保留丢帧、饱和与接触不匹配报告；缺失字段回到采集端补齐，不补造测量值。
5. 先按轨迹／位置／形状尺寸条件确定分区，再导出逐 episode 的 NPZ 和 `manifest.json`。
6. 使用 `python -m tacdex validate --manifest <manifest.json>` 做字段和划分检查。元数据校验不能代替对原始采集程序与物理刺激的检查。
7. 第一阶段只在 `align_train` 拟合尺度；下游与测试复用保存的尺度。不要在采集端逐帧归一化力或深度，避免丢失绝对载荷信息。

当前训练文件的 taxel mask 为每片传感器静态 `[N]`。对于随时间变化的缺测或饱和，应由导出器整帧剔除／按契约标无效，或先明确扩展动态 mask；当前模型不隐含支持 `[T,N]` 动态 mask。深度有效 taxel 上不得留 NaN，不能通过随意补零制造“无接触”。

## 6. 交付目录建议

```text
dataset_delivery/
├─ raw/                         真机与仿真原始记录
├─ calibration/                 taxel 表、轴变换、零偏／单位、版本
├─ simulation/                  模型版本、碰撞与 solver 配置、来源清单
├─ quality/                     时序、重复包、接触一致性和饱和统计
└─ processed/
   ├─ manifest.json             schema_version=2、固定分区
   └─ episodes/*.npz            每条独立轨迹一个文件
```

这是外部数据交付建议，不表示仓库已经实现原始 SDK／replay 的一键转换器。当前 `adapters.py` 提供已解码数组的 ID3 提取、几何 CSV 读取、最近时间匹配和旧文件字段检查；消息解析、标定与完整导出仍需与实际 SDK 格式对接。

## 7. 进入正式训练前的验收清单

- [ ] 真机逐 taxel 三轴力、真机模块合力、仿真逐 taxel 深度、仿真直接合力四项齐全。
- [ ] 四项都只描述 ID3；三轴顺序、符号、单位、taxel 顺序和几何版本已核对。
- [ ] 仿真合力来源是直接求解器输出；未使用 RBF taxel 力作为输入或深度替代。
- [ ] 真实独立触觉包可追溯、无重复计数，时间误差及采样频率有统计。
- [ ] 物理刺激已对应；真机与仿真均能在 ID3 上观察到预期接触。
- [ ] 每条轨迹有完整历史窗口，加载／保持／卸载和无接触阶段有标记。
- [ ] 缺测、饱和与坏 taxel 有处理依据，缺失数据未被伪装为零读数。
- [ ] 按组划分数据；下游真机测试及 OOD 条件没有进入模型选择或归一化拟合。
- [ ] 原始来源、标定、模型和配置可追溯，正式数据 `synthetic=false`。
- [ ] 数据校验通过；人工复核接触样例后再开始正式训练。
